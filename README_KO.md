# Tin Oxo Studio 4.1 — localhost 브라우저 / Python

## 4.1 웹 실행 안내

4.1부터 기본 실행 화면은 로컬 웹 브라우저입니다. 아래의 기존 Tk 설명은 `--native` 실행 시에 해당합니다. 기존의 Python 화학 처리와 파일 형식은 유지합니다.

```bash
python TinOxoStudio.py --port 8888
```

포트를 생략하면 터미널에서 번호를 묻습니다(기본 8765). 입력한 포트에 서버가 열린 뒤 기본 브라우저로 자동 접속합니다. 주소는 `http://127.0.0.1:8888/#token=…` 형식입니다. 토큰이 포함된 전체 주소를 사용하세요. 포트 0은 빈 포트를 자동 선택하며, 이미 사용 중인 포트에는 연결하지 않습니다. 입력 가능한 터미널이 없고 포트를 생략하면 8765를 사용합니다.

- `--no-browser`: 자동 브라우저 실행을 끕니다. 서버/SSH 환경에서 사용합니다.
- `--config-dir DIR`: 프로젝트 복구와 설정을 보관할 별도 폴더입니다.
- `--fresh`: 지난 웹 작업 복구 대신 빈 Sn12 코어로 시작합니다.
- `python TinOxoStudio.py FILE --port 8888`: 지정 파일을 우선 불러옵니다.
- `--native`: 기존 Tk/X11 편집기를 엽니다. 필요한 경우 `conda install -c conda-forge tk=8.6 fontconfig`로 설치하세요.
- 종료는 서버 터미널에서 Ctrl+C입니다. 브라우저 탭만 닫으면 서버는 계속 실행됩니다.

HPC에서는 PC에서 `ssh -L 8888:127.0.0.1:8888 user@server`로 접속하고, 서버에서 `python TinOxoStudio.py --port 8888 --no-browser`를 실행한 뒤 PC 브라우저에서 출력 주소를 여세요. MobaXterm의 SSH 터널 기능으로도 같은 포트를 전달할 수 있습니다. **웹 모드는 DISPLAY나 X11 전달을 사용하지 않습니다.** 원격 실행 시 자동 열기는 서버의 브라우저를 대상으로 하므로 `--no-browser`를 사용합니다.

브라우저의 글꼴 렌더러가 버튼·메뉴·본문을 직접 표시합니다. Windows에서 접속하면 Windows에 설치된 맑은고딕/굴림/Arial/Calibri를 사용할 수 있고, 없는 글꼴은 함께 제공하는 나눔고딕 등으로 대체됩니다. UI와 리간드 팝업은 HTML/CSS/SVG로 표시하며 분자 뷰어는 WebGL, 미지원 시 Canvas 2D를 사용합니다. 화면 회전은 서버 왕복 없이 처리합니다. 인터넷/CDN/Node.js는 실행에 필요하지 않습니다.

웹 화면에서도 코어/선택/좌표 편집, SVG 리간드 결합 원자 선택, 일괄 부착, MMFF/UFF 정리, 결합/접촉/공명/기하 검사, 보관함과 실행 취소, Gaussian 간편/커스텀 설정을 사용합니다. 기존 Tk 전용 OS 글꼴 파일 설치와 X11 FPS 옵션은 `--native`에서 사용합니다. 웹 브라우저에서는 접속 PC의 글꼴과 브라우저 렌더링을 사용합니다.

### 웹 파일 저장 위치

- 웹 편집 결과는 서버의 `~/.config/tinoxo-studio/web-workspace.json`에 자동 복구 저장합니다. `--config-dir`와 `TINOXO_CONFIG_DIR`로 변경할 수 있습니다. 여러 서버는 서로 다른 폴더를 지정하세요.
- **프로젝트 JSON 다운로드**와 구조/이미지/CSV 다운로드는 브라우저가 열린 PC에 저장됩니다.
- **서버 경로에 저장**은 파일 이름을 포함한 경로를 입력해 Python 서버 쪽에 저장합니다. Gaussian `.gjf`도 두 경로로 저장할 수 있습니다.
- JSON 저장에는 구조, 결합, 리간드 원자 선택, 구조 보관함, 사용자 SMILES와 화면 설정이 포함됩니다. 이전 3.x/4.0 프로젝트를 불러올 수 있습니다.
- 계산은 백그라운드에서 진행하며 취소 요청 이후 결과는 적용하지 않습니다. 계산 중 다른 구조 편집은 막고, 동일 서버의 다른 탭에서 변경된 버전은 재확인하도록 합니다.

서버는 기본적으로 `127.0.0.1`에만 연결을 허용하며 실행마다 만든 토큰으로 편집 API를 보호합니다. 로컬/SSH 전달 용도의 단일 사용자 도구입니다. 공개 인터넷 서비스로 배포하는 구성은 포함하지 않습니다.

## 기존 Tk 편집기와 과학 처리 설명

아래의 설치/메뉴/파일 대화상자 설명은 4.0 기반 Tk 편집기의 사용법입니다. 4.1에서 기본 실행하려면 위 웹 안내를 따르고, 이 화면을 실행하려면 명령에 `--native`를 붙이세요.


서버에서 `python TinOxoStudio.py --native`로 실행하는 네이티브 Tkinter 편집기입니다. 구조 표시도 Tk Canvas에서 소프트웨어로 처리하므로 브라우저, JavaScript 서버, OpenGL, GPU가 필요하지 않습니다. 리간드 생성·힘장 계산은 서버 CPU에서 수행합니다. 코어 좌표·리간드 목록·기본 색상·구형 HTML 호환 코드는 메인 `.py`에 내장되어 있습니다. `fonts/` 폴더는 Windows 글꼴이 없는 HPC를 위한 오프라인 대체 글꼴이므로 함께 복사하세요.

## 1. 설치와 실행

### 권장: 독립 Conda 환경

패키지를 HPC 작업 디렉토리에 풀고 다음을 실행합니다.

```bash
conda env create -f environment.yml
conda activate tinoxo
python TinOxoStudio.py --check
python TinOxoStudio.py
```

다음처럼 직접 설치할 수도 있습니다.

```bash
conda create -n tinoxo -c conda-forge python=3.11 tk=8.6 rdkit ase numpy scipy pillow
conda activate tinoxo
python TinOxoStudio.py
```

기존 Python 환경에 Tk가 있는 경우:

```bash
python -m pip install -r requirements.txt
python TinOxoStudio.py
```

`tkinter`는 일반적인 pip 패키지로 설치하지 않습니다. Conda의 `tk` 또는 HPC에서 제공하는 Python/Tk 모듈을 사용하세요. Python 3.10 이상이 필요하며 권장 환경은 Python 3.11 + Tk 8.6입니다. 테스트에서는 Python 3.12/Tk 9와 Python 3.13/Tk 8.6도 사용했습니다. Tk 9의 일부 빌드는 X11 글꼴 표시가 좋지 않아 Tk 8.6 환경을 권장합니다.

### MobaXterm

1. MobaXterm의 X server를 켭니다.
2. SSH 세션 설정의 X11 forwarding을 켜고 HPC에 다시 접속합니다.
3. 서버에서 다음을 확인합니다.

```bash
echo "$DISPLAY"
python -m tkinter
```

테스트 창이 뜨면 닫고 편집기를 실행하세요. `DISPLAY`는 SSH가 부여한 값을 사용합니다. 임의로 `:0`으로 덮어쓰지 마세요. 직접 SSH 명령으로 접속할 때는 서버 정책에 맞춰 `ssh -X` 또는 `ssh -Y`를 사용할 수 있습니다.

로그인 노드 사용 정책상 계산이 제한되면 X11을 지원하는 대화형 계산 노드에서 실행하세요. 배치 노드로 옮길 때도 해당 클러스터의 X11 전달 방식을 따라야 합니다. 이 프로그램은 스케줄러 작업을 자동 제출하지 않습니다.

4.0은 동봉한 나눔고딕/Carlito를 프로세스에 직접 등록하므로 일반적인 Linux Fontconfig 환경에서는 별도 `fc-cache`나 관리자 권한이 필요하지 않습니다. Conda 설치는 `fontconfig`도 포함합니다. 정확한 맑은고딕·굴림·Arial·Calibri 사용 방법은 아래 글꼴 항목을 참고하세요.

예제 구조를 바로 열려면 다음을 실행합니다.

```bash
python TinOxoStudio.py examples/Sn12_Methyl.tinoxo.json
```

## 2. 빠른 사용 순서

1. 왼쪽에서 Sn12 / Sn6 / Sn3를 선택하고 **빈 코어로 초기화**를 누릅니다.
2. 단일 / 다중 / 사각형 선택으로 원자를 고릅니다. **모든 Sn**, **전체**, **연결 H까지**, **리간드 전체**도 사용할 수 있습니다.
3. **선택 원자에 리간드 붙이기**를 엽니다.
4. 공통 입력은 **선택 원자 모두**, 원자별 입력은 개별 대상 원자를 고릅니다.
5. SMILES를 입력하거나 **범용 리간드 / 내 SMILES에서 선택**합니다. 라이브러리의 **선택 사용** 또는 더블클릭 시 결합 원자 팝업이 열립니다.
6. 팝업의 구조를 클릭하거나 오른쪽 목록에서 결합 원자를 고르고 **결합 원자 확정**을 누릅니다. 직접 SMILES를 입력했다면 **결합 원자 선택…**을 사용하세요. 선택하지 않고 계획 추가/적용을 눌러도 먼저 팝업이 열립니다.
7. 각 줄을 **입력을 계획에 추가**로 모은 뒤 **모두 적용**합니다. 같은 선택을 모든 대상에 적용하며, 줄마다 결합 원자·방식·길이·방향을 따로 지정할 수도 있습니다.
8. 계산 / 검사 탭에서 MMFF94 또는 UFF를 선택하고 최적화합니다.
9. 결합 검사와 거리·각도를 확인하고 프로젝트를 저장합니다.

구조를 돌리려면 왼쪽 드래그, 확대는 휠, 이동은 우클릭 드래그입니다. 사각형 선택 모드에서는 앞·뒤 원자 중심을 함께 선택합니다. Shift는 추가 선택이고 Alt+드래그는 회전입니다. 선택 원자는 청록색 외곽선과 순서 번호로 구분합니다. 왼쪽과 선택 패널에는 세로 스크롤바가 있어 작은 화면에서도 아래 항목을 사용할 수 있습니다.

### 코어 및 결합 자리

| 코어 | 빈 코어 | 기존 리간드 자리 |
|---|---|---|
| Sn12 | Sn12O20H6: 원본 Sn12O14(OH)6 좌표 | R 12개 |
| Sn6 | Sn6O6 문헌 좌표 | R 6개, 카복실레이트 L 6개 |
| Sn3 | Sn3O3, 정확히 Sn 3개 + O 3개 | R 3개, 포스피네이트 P 3개 |

Sn3는 기존 O-capped Sn3O(OH)3 모델에서 중앙 μ3-O와 H 3개를 실제 제거한 고리입니다. 문헌의 완성 화합물과 다른 사용자 설계 골격이므로 기존 +1 전하를 이어받지 않으며, 전하·양성자화 상태를 직접 정해야 합니다. 원래의 Sn/O 좌표와 고리 연결을 보존합니다.

**Sn12 OH 6자리 → 리간드**는 코어 H 6개를 실제 제거하고 그 O 6개를 선택합니다. 이미 제거한 경우 같은 O 자리를 다시 선택할 수 있습니다. 추가한 리간드의 OH는 지우지 않습니다. 입력창을 닫아도 H 삭제는 유지되며 실행 취소로 복원할 수 있습니다.

4.0에서는 **입력 SMILES의 원자 번호**를 팝업과 실제 부착에 동일하게 사용합니다. 화면 번호는 1부터, 저장 필드 `attachmentIndex`는 0부터 시작합니다. SMILES 순서를 바꾸지 않으므로 가지·방향족·입체정보의 원자 대응이 유지됩니다. 예를 들어 `CCN`을 입력해 N3을 고르면 세 번째 N이 부모 원자에 붙습니다. 번호는 코어의 원자 ID와 다릅니다.

`covalent`는 선택 원자의 H 하나를 치환합니다. H가 없고 별표 연결점도 없는 포화 원자는 목록에서 제외합니다. `coordinate`는 선택 원자의 H를 유지하며 해당 원자를 donor로 사용합니다. `[*:1]C` 같은 별표는 최초 선택의 제안으로 쓸 수 있습니다. 별표와 다른 원자를 고르면 기존 별표를 H로 막고 새 원자의 H를 치환합니다. 배위결합에서는 별표를 H로 막은 완전한 리간드를 사용합니다. 팝업 취소는 구조를 바꾸지 않습니다. SMILES나 결합 방식을 바꾸면 다시 원자를 선택해야 합니다.

L/P 자리에는 `CC(=O)[O-]`, `CP(C)(=O)[O-]`처럼 donor O 두 개가 있는 전체 리간드를 입력합니다. 선택한 O는 첫 번째 Sn, 같은 연결부의 다른 O는 두 번째 Sn에 연결합니다. 연결부가 여러 개라면 선택한 O가 속한 연결부를 사용합니다. 산 형태는 해당 가교 donor를 탈양성자화합니다. 양성자화 상태를 임의로 일반화하지 않습니다. R 자리는 Sn–C이므로 탄소만 선택할 수 있습니다.

## 3. RDKit 초기 구조 생성과 최적화

SMILES 해석 → 결합 원자 선택 → 원자가/방향족 검증 → 명시적 H → ETKDGv3 다중 conformer → 선택한 힘장 → 낮은 힘장 에너지 conformer 선택 → 코어 부착 순서입니다. 별표는 H로 막아 유기 조각을 생성합니다. 공유결합에서는 선택한 원자의 H 또는 그 자리에 대응하는 cap H 하나를 제거합니다.

| 범위 | 동작 |
|---|---|
| 리간드 / 코어 고정 | 공유결합 경계를 H로 막고 부착 원자·가교 donor·사용자 고정 원자를 유지해 유기 조각을 최적화합니다. 이후 가능한 자리의 축 회전으로 겹침을 줄입니다. |
| 전체 / 지정 고정 원자 유지 | RDKit이 전체 구조를 해석하고 모든 MMFF/UFF 파라미터가 있는 경우에만 실행합니다. 원자의 고정 플래그를 유지합니다. |

MMFF94/UFF가 지원하지 않는 구조에는 다른 힘장을 몰래 적용하지 않고 오류를 표시합니다. 특히 Sn 다배위 코어는 전체 힘장 계산이 불가능할 수 있습니다. 파라미터가 있다고 해도 금속계에 대한 정확성을 보장하지 않습니다. 코어 원자는 처음에 고정되어 있으며 선택 패널에서 고정/해제할 수 있습니다.

단원자 F/Cl/Br/I 리간드는 부착 후 내부 자유도가 없으므로 조각 최적화를 생략합니다. 전하나 배위 결합을 포함한 Sn 계의 최종 구조·상대에너지는 적절한 DFT 계산으로 검토해야 합니다.

작업 기록의 에너지는 kcal/mol이며, 리간드 범위에서는 H로 막은 고립 조각의 값입니다. 리간드 에너지 합을 클러스터 총에너지로 해석하거나 서로 다른 범위·힘장의 에너지를 직접 비교하면 안 됩니다. 반복 제한 도달 여부도 기록합니다. 계산 중에는 화면 회전이 가능하고 작업 취소는 결과 적용을 취소합니다.

### 공명 처리

- RDKit으로 공명식과 방향족/공액 결합을 식별합니다. 선택한 리간드 또는 직접 입력한 SMILES의 Lewis 표현을 확인할 수 있습니다.
- 생성 좌표는 RDKit의 기하와 힘장으로 구합니다. 공명식 열거만으로 전자밀도, Wiberg 차수, DFT 결합길이를 계산하지 않습니다.
- UFF가 하나의 Lewis 표현을 따라 고립 카복실레이트 또는 니트로기의 동등한 말단 O에 서로 다른 길이를 부여하는 경우, RDKit MMFF94 평형거리를 기준으로 등가거리 제약을 추가합니다. 적용한 중심·O·목표거리는 프로젝트의 리간드 메타데이터에 기록합니다. 이 경우 에너지는 제약이 포함된 UFF 값입니다.
- 이 보정은 두 말단 O가 동등하고 수소/치환기가 없는 제한된 경우에만 적용합니다. 인산계 등 모든 공명 결합을 임의로 평균화하지 않으며 비대칭 금속 배위 환경의 C–O 길이를 같게 강제하지 않습니다.
- 공명식 개수가 1개로 나와도 공명이 없다는 의미는 아닙니다. RDKit이 주어진 열거 규칙에서 제공한 표현의 수입니다. 공액 결합 인식은 별도로 보존합니다.
- 화면의 `meanFormalOrder`는 열거된 형식차수의 산술평균으로, 양자화학적 결합차수나 공명식의 물리적 가중치가 아닙니다. 힘장 그래프나 Gaussian 입력에 이 평균을 넣지 않습니다.

가교 리간드는 donor 두 개와 중심을 기준으로 문헌 자리에 강체 정렬합니다. 원본 위치에 억지로 맞추기 위해 유기 결합을 늘이지 않습니다. 정렬 오차 `fitRMSD`는 검사 보고서에 기록되며 큰 오차는 별도 구조 검토가 필요합니다.

## 4. 결합·접촉·기하 검사

명시된 결합 그래프는 거리 때문에 사라지지 않습니다. 파일/SMILES의 연결을 우선하고, ASE 이웃 목록과 금속 donor 거리 규칙으로 빠진 연결 후보를 제시합니다. 결합 검사 창에서 후보를 선택해 추가하거나 원자 ID 2개를 입력해 결합을 직접 추가·삭제·수정할 수 있습니다.

ASE 자체는 양자화학적 결합차수를 판정하지 않습니다. 금속 결합의 존재·차수·산화상태도 거리만으로 확정하지 않습니다. 긴 기존 결합은 삭제하지 않고 확인 표시를 합니다. 유기 리간드의 RDKit 원자가 검사와 금속의 명시 그래프 배위수도 확인할 수 있습니다.

XYZ에는 결합 정보가 없으므로 비금속 분자는 RDKit xyz2mol을 시도하고, 실패하거나 금속이 있으면 ASE 기반 잠정 연결을 표시합니다. 전하가 주어지지 않은 XYZ의 자동 추정은 틀릴 수 있어 불러온 뒤 결합 검사에서 확인해야 합니다. 결합차수를 보존하려면 프로젝트 JSON 또는 SDF를 사용하세요.

원자 2개는 거리, 3개는 가운데 원자를 꼭짓점으로 하는 각도, 4개는 입력 순서의 이면각을 계산합니다. 전체 명시 결합 길이와 연결된 각도 목록을 CSV로 저장할 수 있습니다.

접촉 검사 기본값은 `max(vdW 반경합 × 0.75, 공유반경합 × 1.18)`입니다. 공통 최소 거리 모드도 있습니다. 1–2, 1–3 및 코어 내부 쌍은 제외합니다. 자동 부착은 기존 O–H 방향과 현재 주변 방향을 기준으로 후보 방향·회전을 탐색하지만, 큰 리간드가 반드시 모두 들어가는 것은 아닙니다. 남은 접촉을 확인하세요.

이 앱은 유한 클러스터를 대상으로 합니다. CIF 등 주기 구조를 읽을 수는 있지만 표시/기하/접촉 검사는 주기경계의 최소 이미지를 계산하지 않습니다.

## 5. 색상·화면·즐겨찾기

다크/라이트, 한글 글꼴 **맑은고딕 / 굴림**, 영문 글꼴 **Arial / Calibri**, 크기, 본문·제목·설명·버튼·입력값·상태·경고·3D 라벨 색상, 선택 강조 색상을 설정합니다. 다른 문자·언어용 글꼴을 임의로 선택하는 목록은 제거했습니다.

Windows 글꼴이 실제로 HPC에 설치되어 있으면 그 글꼴을 사용합니다. 없으면 동봉한 나눔고딕/Carlito로 대체하고 설정 창과 상태 줄에 실제 표시 글꼴을 알려 줍니다. Microsoft 글꼴 바이너리는 포함하지 않습니다. `C:\Windows\Fonts`의 사용 권한이 있는 `malgun.ttf`, `gulim.ttc`, `arial.ttf`, `calibri.ttf` 등을 MobaXterm SFTP로 HPC에 복사한 뒤 **화면 설정 → 글꼴 파일 추가**에서 선택하세요. 이 파일 대화상자는 Windows PC가 아닌 HPC의 경로를 표시합니다. 직접 `fonts/user/`에 넣거나 `TINOXO_FONT_DIR`로 서버 글꼴 폴더를 지정한 뒤 실행할 수도 있습니다.

혼합 한영 UI 문구는 한글을 안전하게 표시하는 글꼴을 사용합니다. 영문 입력란·XYZ·Gaussian·3D 원자명은 영문 글꼴을 사용하며, 텍스트 창에 섞인 한글은 별도 글꼴 태그로 표시합니다. 미리보기에는 한글/영문 예문과 실제 사용 글꼴이 나옵니다. PNG/SVG 원자명도 해석된 영문 글꼴을 사용합니다.

4.0은 Tk 창 생성 전에 Linux Fontconfig에 윤곽선 글리프, 회색조 안티앨리어싱과 힌팅을 설정합니다. 작은 CJK 내장 비트맵을 피하고 설명 글꼴은 최소 10 pt로 표시합니다. 사용자·시스템의 글꼴 설정 파일은 수정하지 않습니다. Windows는 창 전체가 저해상도 비트맵으로 확대되지 않도록 시작 시 DPI awareness를 설정합니다. 설정 창에서 현재 텍스트 처리 방식과 화면 DPI를 확인할 수 있습니다. 리간드 팝업은 2배 크기로 그린 뒤 축소한 선명한 구조 그림을 사용합니다. 원격 데스크톱이나 MobaXterm 창 자체가 OS에서 확대되는 경우의 표시 품질은 연결 환경에도 영향을 받습니다.

소스와 저장 파일은 UTF-8입니다. BOM이 있는 UTF-8 및 이전 CP949 한국어 텍스트를 읽고, 다시 저장할 때는 UTF-8로 통일합니다. 읽지 못하는 바이트를 대체 문자로 덮지 않고 오류를 표시합니다. 글꼴이 글리프를 갖지 않아 생기는 네모/깨짐과 파일 인코딩 문제는 구분하여 처리합니다.

**뷰어 동작:** 구조의 회전 중심과 픽셀/Å 배율을 보관합니다. 회전, 이동, H/코어 표시 전환, 창 크기 변경은 배율을 바꾸지 않습니다. 휠로 확대·축소하며, **맞춤**은 전체 구조의 회전 불변 경계를 기준으로 다시 맞추고 줌/이동을 초기화합니다. 구조를 새로 만들거나 불러와 전체 맞춤을 수행하는 작업은 새 구조에 맞춰집니다.

도형을 매 프레임 삭제하지 않고 재사용하며, 좌표/깊이 갱신을 묶어 처리합니다. 기본 목표 프레임은 30이며 설정에서 15/20/30/60을 선택할 수 있습니다. 회전·이동 중에는 결합 분할과 음영을 줄이고, 큰 구조의 비선택 라벨을 잠시 생략합니다. 원자와 결합 좌표·가시성·선택은 유지하며 마우스를 놓으면 상세 표시를 복원합니다. 경량 표시를 끌 수도 있습니다. 목표 프레임은 처리 속도 보장이 아니며 실제 MobaXterm 연결 성능은 RTT·대역폭·서버 부하에 영향을 받습니다. VESTA 3.5.8의 원소 RGB 숫자를 기본으로 사용합니다. 해당 버전에 색상이 정의되지 않은 초중원소는 VESTA의 XX 회색 기본값을 사용합니다. 118개 원소 모두 개별 변경할 수 있고 서버에 있는 다른 버전의 `elements.ini`도 읽을 수 있습니다. VESTA 프로그램 자체는 포함하지 않습니다.

선택 원자 색상은 원소 기본값과 별도로 그 원자에 적용합니다. 내 SMILES는 리간드 창에서 이름·SMILES·결합 방식을 입력해 저장합니다. 내장 목록을 편집한 사본도 저장할 수 있습니다.

설정은 `~/.config/tinoxo-studio/settings.json`에 기록합니다. 경로는 다음처럼 바꿀 수 있습니다.

```bash
export TINOXO_CONFIG_DIR="$PWD/tinoxo-settings"
python TinOxoStudio.py
```

## 6. Gaussian 16 입력 생성

상단 **Gaussian 16**에서 다음을 지정할 수 있습니다.

| 탭 | 사용 방법 |
|---|---|
| 간편 설정 | 방법/XC와 기저함수를 나란히 선택하고 파동함수·작업·총전하·다중도·CPU·메모리·용매를 설정합니다. 기저함수를 목록에서 선택하거나 **이 기저함수를 모든 원소에 간편 적용**을 누르면 원소별 지정을 지우고 mixed/Auto로 통일합니다. |
| 커스텀 설정 | **방법 / 기저함수 / ECP** 화면에서 XC 조합, 기본/원소별 기저함수 및 ECP, 외부 Gen/GenECP 블록을 함께 설정합니다. 내부의 SCF/최적화/물성과 추가 입력 화면에서 세부 항목을 조절합니다. |
| 입력 미리보기 | 두 탭이 공유하는 현재 설정으로 입력을 생성하고 저장합니다. 탭을 바꾸는 것만으로 설정이 초기화되지는 않습니다. |

방법·파동함수 등 일반 선택 칸은 이전 기본 32자에서 16자, 고급 칸은 52자에서 26자로 줄였습니다. 창을 넓혀도 해당 칸은 자동으로 길어지지 않습니다. 긴 사용자 키워드는 입력 칸 안에서 가로로 이동하며 편집할 수 있습니다.

- 방법/XC: B3LYP, PBE1PBE, PBEPBE, BLYP, BP86, M06 계열, TPSSh/TPSSTPSS, wB97XD, CAM-B3LYP, HF, MP2, CCSD 계열 및 직접 입력.
- 일부 exchange/correlation 조합 선택, R/U/ROHF 선택, 총전하, 스핀 다중도.
- SP, Opt, Opt+Freq, Freq, TD-DFT, NMR, Polar, Force, TS.
- CPU, 메모리, 체크포인트, 코어 또는 사용자 지정 고정 원자.
- SCF 수렴/반복/XQC·QC, 수치 격자, 최적화 반복, 분산 보정, population, 용매 SMD/IEFPCM, TD 상태 수/Root, 추가 route 키워드.
- 단일 기저함수, 원소별 혼합 기저함수/ECP, 직접 입력하는 Gen/GenECP 블록.

Sn에 def2를 사용하면 Auto 설정에서 `GenECP`와 `Sn 0 / Def2` ECP 부분을 생성합니다. Sn에 6-31G 등을 그대로 지정하는 알려진 부적합 조합, 전자수/다중도 홀짝 불일치, 분산이 포함된 방법에 GD3를 중복하는 경우 등을 검사합니다. 모든 방법·기저함수·Gaussian revision의 호환성을 완전하게 판정하는 것은 아닙니다.

**입력 생성 / 갱신**으로 미리보기를 확인하고 **HPC 경로에 .gjf / .com 저장**을 누르세요. 파일 대화상자에 표시되는 디렉토리는 HPC 서버의 실제 경로입니다. 저장은 원자적으로 처리합니다. Gaussian을 실행하거나 작업을 제출하지 않으므로 편집기에 Gaussian 실행파일을 연결할 필요는 없습니다.

구조를 삭제·치환한 후 전하는 자동으로 확정하지 않습니다. 총전하와 스핀 다중도를 직접 확인하세요. 핵 전하 합에서 총전하를 빼 전자수 홀짝을 확인하며, 대표적인 Sn ECP는 짝수 전자를 대체하므로 이 홀짝 검사가 유지됩니다. 원자별 형식전하 합과 별도로 입력한 총전하를 관리합니다.

입력 생성기는 현재 Cartesian 좌표를 사용하는 단일 작업을 대상으로 합니다. 현재 좌표를 쓰는 입력과 `Geom=Check/AllCheck`를 섞는 입력은 허용하지 않습니다. 추가 route는 고급 사용자용이며 별도 입력 섹션이 필요한 임의 키워드는 직접 검토해야 합니다. 다중 Link1, ONIOM, QST2/QST3/IRC용 복수 구조 생성은 이번 버전의 전용 UI에 포함하지 않았습니다.

### Gaussian 문서 확인 기록

2026-11-06에 공식 `gaussian.com`의 input, basissets, dft, gen, opt, link0 페이지를 요청했으나 HTTP 403/502 또는 timeout으로 본문을 받지 못했습니다. 공식 링크를 도움말에 넣고, CON FLEX가 제공하는 Gaussian 16 매뉴얼의 입력·DFT·Basis Sets·GenECP·Opt 문서로 구문을 대조했습니다. 생성 파일의 구조·전자수·ECP 블록은 자동 검사했지만 실제 Gaussian 16 실행파일로 계산을 실행한 검증은 하지 않았습니다.

## 7. 저장과 복구

`.tinoxo.json` 프로젝트는 현재 구조, 명시 결합, 리간드 자리, 공명/최적화 메타데이터, 이름별 보관함, 즐겨찾기, 화면 설정을 보존합니다. 보관함에서 이름별 저장·복사·불러오기·이름 변경·삭제·복원을 지원합니다. 프로젝트 파일 저장은 별도로 눌러야 합니다.

XYZ, SDF V3000, PDB, PNG, SVG, JSON 검사 보고서를 내보낼 수 있습니다. SDF의 원자 형식전하가 금속 코어에 미할당일 수 있어 사용자 총전하를 별도 필드에 기록합니다. PDB는 결합차수 보존용 형식이 아닙니다.

호환 HTML 내보내기는 기존 v2.2 웹 편집기와 프로젝트를 포함합니다. 브라우저에서는 기존 웹 기능을 사용하며 새 RDKit/ASE/Gaussian 기능은 Python 프로그램에서 실행합니다. Python 프로그램은 해당 HTML과 이전에 만든 HTML/JSON을 읽을 수 있습니다.

50단계 실행 취소/복원과 30초 임시 백업을 지원합니다. 정상 종료 시 저장 여부를 묻고, 비정상 종료 후에는 임시 작업 복구를 제안합니다. 임시 백업은 정식 프로젝트 저장의 대체물이 아닙니다.

## 8. 검증과 참고

4.0은 로컬 X11/Tk 8.6에서 총 72개 검사를 통과했습니다. 첫 원자가 아닌 결합 원자, 공유/배위 H 처리, 가교 donor 순서, 선택 위치 저장/재편집, 팝업 클릭/취소, 일괄 부착/실행 취소, Gaussian 두 탭의 값 공유와 선택 칸 폭을 포함합니다. 기존 배율·글꼴·인코딩 검사도 통과했습니다. 실제 사용자의 HPC/MobaXterm 세션에서는 시험하지 못했습니다. 상세 수치는 VALIDATION.md를 참고하세요.

```bash
python TinOxoStudio.py --check
python -m unittest discover -s tests -v
python TinOxoStudio.py --export-core 3 --output Sn3O3.xyz
```

과학 처리 회귀검사에는 코어 좌표 보존, Sn3 고리, OH 자리, 공유/배위 부착의 H 처리, 방향족 평면성, MMFF/UFF 카복실레이트, 가교 배치, 힘장 실패/취소, 결합 후보, 기하, 파일 왕복, Gaussian 전자수·기저/ECP·작업 종류가 포함됩니다. 로컬 X11 서버에서 메인 GUI 및 각 대화상자를 실행했습니다. 사용자의 실제 HPC와 MobaXterm 연결, Gaussian 16 실제 계산은 이 환경에서 직접 시험할 수 없었습니다.

- RDKit: https://www.rdkit.org/docs/RDKit_Book.html
- RDKit force fields: https://www.rdkit.org/docs/source/rdkit.Chem.rdForceFieldHelpers.html
- RDKit xyz2mol: https://www.rdkit.org/docs/source/rdkit.Chem.rdDetermineBonds.html
- ASE: https://docs.ase-lib.org/ase/neighborlist.html
- VESTA: https://jp-minerals.org/vesta/en/doc/VESTAch12.html
- Gaussian 공식: https://gaussian.com/input/ , https://gaussian.com/basissets/ , https://gaussian.com/dft/ , https://gaussian.com/gen/
- CON FLEX G16 매뉴얼: https://www.conflex.co.jp/gaussian_support/

코어 좌표 출처는 프로그램과 프로젝트 메타데이터에도 보존합니다.

- Sn12: Sadegh et al., DOI 10.1021/acs.jpcc.3c07480; 공개 좌표 데이터 DOI 10.21942/uva.24574750, CC BY 4.0.
- Sn6: Reichelt & Reuter, DOI 10.1107/S160053681204888X, 공개 결정구조.

- Sn3 phosphinate 모티프: Day et al., DOI 10.1021/ja00237a072. 배치한 리간드는 원래 결정 화합물의 재현을 뜻하지 않습니다.
